# PRD: NoLight
*Робоча назва — підтвердити.*

## 0. Призначення документа
PRD для власника проєкту (Богдан) та подальших BMAD-воркфлоу (архітектура, епіки, історії). Словник термінів (§3) обов'язковий для всіх артефактів. Рівень строгості: особистий застосунок і(публічний випуск на цьому етапі не розглядається). Документ у стані чернетки; відкриті питання — у §8.

## 0.1 Поточний стан
Версія v1 уже існує: розбір офіційного сайту для Черкас, вибір підчерги, віджети (малий/середній/великий), кеш, кнопка оновлення, версіонування. Цей PRD описує розвиток від v1: усе, що позначено нижче, — нове, крім FR-15 (віджети — розширення наявного). Під «MVP» мається на увазі наступний реліз після v1.

## 1. Бачення
Нативний iOS-застосунок, який показує, коли є і коли немає електроенергії, для будь-якого місця в Україні: дім, робота, пункт призначення в подорожі. Головне питання, на яке він відповідає з першого погляду: «коли в мене вдома або на роботі буде чи не буде світла?».

Застосунок допомагає планувати день (коли їхати додому, коли лишитися на роботі), вчасно запускати генератор і не пропускати зміни графіків. Користувач сам вибирає джерело даних, бачить його надійність і кастомізує вигляд під себе.

## 2. Цільовий користувач

### 2.1 Jobs To Be Done
- Швидко зрозуміти, коли вдома та на роботі буде світло.
- Спланувати день і поїздки навколо графіка відключень.
- Запускати і зупиняти генератор без збоїв у живленні.
- Дізнаватися про зміну графіка, не відкриваючи застосунок.
- Перевірити, чи буде світло у місці призначення до моменту приїзду.

### 2.2 Не користувачі (v1)
Енергетики, постачальники та ті, кому потрібні адресні відключення «за вулицею/будинком» поза чергами та підчергами.

### 2.3 Ключові сценарії

- **UJ-1. Богдан зранку планує день між домом і роботою.**
  Вдома та на роботі різні підчерги. Він відкриває застосунок і одразу бачить два місця, «Дім» і «Робота», з поточним станом, найближчою зміною та шкалою на 24 години. Вирішує, чи затриматися на роботі, чи виїхати, поки вдома є світло.
- **UJ-2. Богдан готує генератор на роботі.**
  За налаштований час до відключення приходить сповіщення, і він вчасно запускає генератор для безшовного перемикання. Перед поверненням світла приходить друге сповіщення, і він зупиняє генератор.
- **UJ-3. Графік змінився.**
  Богдан отримує сповіщення, бо обленерго оновило графік: «Графік для «Робота» змінився» зі старим і новим графіком.
- **UJ-4. Богдан у подорожі.**
  Він купує квиток на потяг або автобус на 2-3 години дороги. Не зберігаючи місця, вибирає область і чергу пункту призначення і бачить, чи буде світло в момент приїзду.

## 3. Словник
- **Область** — адміністративний регіон (= «регіон»); першочерговий вибір джерела даних.
- **Черга** — число 1–6 у межах області.
- **Підчерга** — черга з суфіксом .1/.2 (наприклад, 3.2); мінімальна одиниця графіка.
- **Місце** — збережена комбінація «назва + область + черга + підчерга» (Дім, Робота).
- **Графік** — графік станів світла на добу для підчерги.
- **Джерело** — звідки береться графік: офіційний сайт обленерго або API OE_OUTAGE_DATA.
- **Стан** — є світло / немає світла / невідомо.
- **Ніч / День** — інтервали доби для статистики; ніч за замовчуванням 00:00–06:00, решта — день.

## 4. Функції

### 4.1 Місця та вибір підчерги
**Опис:** Користувач створює довільну кількість **місць**. Для кожного вибирає область → чергу → підчергу. Реалізує UJ-1, UJ-2.

#### FR-1: Керування місцями
Користувач може додавати, перейменовувати, змінювати порядок і видаляти місця. Реалізує UJ-1.
- Кількість місць не обмежена, але iOS дозволяє лише 64 локальні сповіщення. Система планує лише найближчі за часом сповіщення й перепланує їх при кожному оновленні та відкритті застосунку. [ASSUMPTION]
- Місце містить назву, область, чергу, підчергу та (для Черкас) вибране джерело.
- Видалення місця скасовує його запланованих сповіщення.

#### FR-2: Каскадний вибір
Список областей відповідає областям, які підтримують джерела. Черги й підчерги залежать від вибраної області. Для області без даних показується пояснення, а не порожній екран.

### 4.2 Головний екран
**Опис:** Перший екран — список місць. Реалізує UJ-1.

#### FR-3: Картка місця
Для кожного місця показано: поточний **стан**, час і тип найближчої зміни, 24-годинну шкалу з маркером поточного часу, позначку свіжості та джерела.
- Кольори стану беруться з налаштувань (FR-20).
- Якщо даних немає, стан «невідомо» (ніколи не «є світло»).

#### FR-4: Деталі місця
Перегляд сьогодні, завтра (якщо є дані) та попередніх днів з інтервалами. Застосунок зберігає історію до 14 днів. [ASSUMPTION]

### 4.3 Режим подорожі
**Опис:** Реалізує UJ-4.

#### FR-5: Перегляд без збереження
Користувач вибирає область, чергу та підчергу без створення місця й бачить графік.

#### FR-6: Стан на час приїзду
Користувач вводить час (або тривалість поїздки) і бачить стан на момент приїзду, а також найближчу зміну після нього. Вимоги до країв доби: якщо приїзд після півночі, використовується графік наступного дня або «невідомо».

### 4.4 Джерела даних
**Опис:** Черкаси за замовчуванням — офіційний сайт обленерго; решта областей — API OE_OUTAGE_DATA. Користувач може для Черкас вибрати API. Реалізує UJ-1, UJ-4.

#### FR-7: Джерела за областями
Система використовує джерело за замовчуванням для області, а для Черкас дозволяє перемикання між сайтом і API.

#### FR-8: Екран порівняння джерел
Для вибраної підчерги Черкас показано графік із сайту та з API поряд, з виділенням різниці, часом оновлення кожного, та кнопкою вибору основного джерела.

#### FR-9: Прозорість і довіра
Кожен графік має позначку джерела; графіки з API мають позначку «неофіційне джерело». Застарілі дані (старші за 1 годину; після 24 годин вважаються протермінованими) [ASSUMPTION] показуються з попередженням.
- Кеш зберігається й показується офлайн із позначкою «оновлено о…».
- Помилка мережі не стирає останній успішний графік.

### 4.5 Статистика
#### FR-10: Показники за період
Користувач бачить кількість годин зі світлом та без, загалом, вночі та вдень за обраний період: сьогодні, попередні дні, завтра (за наявності даних).

#### FR-11: Межі ночі
Користувач налаштовує початок і кінець ночі; за замовчуванням 00:00–06:00, решта — день. Діапазон, що перетинає північ, підтримується.
- Години для днів, де даних немає, не рахуються, а позначаються як «невідомо».

### 4.6 Сповіщення
**Опис:** Реалізує UJ-2, UJ-3.

#### FR-12: Попередження перед відключенням
Користувач для кожного місця налаштовує час попередження (хвилин до відключення). Сповіщення планується локально за кешованим графіком.

#### FR-13: Попередження перед поверненням світла
Те саме, але перед поверненням світла; налаштовується окремо.

#### FR-14: Зміна графіка
Коли оновлення виявляє зміну графіка місця, надсилається сповіщення із коротким підсумком змін. Зміни зберігаються в історії.
- Виявлення залежить від фонового оновлення iOS (див. FR-18, [ASSUMPTION]).
- [NOTE FOR PM] Це must-have (UJ-3), але без власного сервера доставка не гарантована: сповіщення може прийти із запізненням або лише при відкритті застосунку. Власного сервера не буде (див. §5), тож це прийнятий компроміс.
- Після зміни графіка заплановані сповіщення перераховуються.

### 4.7 Віджети та Lock Screen
#### FR-15: Віджети
Малий, середній і великий віджети з вибором місця; кнопка ручного оновлення; стани «застаріло» та «помилка» (вже реалізовано в v1).

#### FR-16: Live Activity / Lock Screen
Зворотний відлік до наступної зміни стану для вибраного місця. [NOTE FOR PM: пріоритет нижчий за FR-12–FR-14.]

### 4.8 Оновлення та налаштування
#### FR-17: Режим оновлення
Користувач вибирає ручне оновлення або автооновлення раз на N хвилин/годин. Мінімум 15 хвилин; пресети 15/30 хв, 1/3/6 год. [ASSUMPTION]

#### FR-18: Фонове оновлення
При автооновленні застосунок реєструє фонове завдання з мінімальним інтервалом із FR-17.
- [ASSUMPTION] iOS сама вирішує, коли виконати завдання, тож інтервал є побажанням. Це має бути зрозуміло показано в налаштуваннях.

*FR-19 вилучено (власний сервер не плануються); номер не перевикористовується.*

#### FR-20: Кольори
Користувач вибирає колір для «є світло» та «немає світла» через color picker або з готових пресетів (включно з варіантами для дальтоніків); пресети перевірені на контраст у світлій і темній темі. Є скидання до стандартних.

### 4.9 Бренд і технічні вимоги
#### FR-21: Логотип та іконка
Створити логотип, іконку застосунку, заставку запуску та іконку віджетів.

#### FR-22: Версіонування
Номер збірки змінюється лише для пушів, що змінюють код застосунку; документація й `_bmad` не змінюють версію. Версія відображається в налаштуваннях.

## 4.10 Наскрізні вимоги
- Усі часи обчислюються за часовим поясом Europe/Kyiv, з коректною обробкою переходу на літній/зимовий час.
- Усі тексти інтерфейсу українською.
- Дані кешуються локально; застосунок працює офлайн із позначкою свіжості.

## 5. Не цілі
- Адресні відключення поза чергами й підчергами.
- Власний сервер або бекенд: не плануються взагалі.
- Публічний випуск в App Store на цьому етапі не розглядається.
- Android та веб.
- Прогнозування відключень.

## 6. Обсяг MVP
### 6.1 У межах
FR-1…FR-14, FR-17, FR-18, FR-20…FR-22 та віджети (FR-15).
### 6.2 Поза межами
FR-16 (Live Activity, залишено в PRD як необов’язкова функція на потім).

## 7. Метрики успіху
- **SM-1** Богдан користується застосунком щодня протягом місяця (особисте використання).
- **SM-2** Сповіщення перед відключенням приходить у межах ±1 хв від налаштованого часу. Підтверджує FR-12, FR-13.
- **SM-3** Частка показів графіка зі свіжістю у межах порогу (1 год) — не менше 90% за тиждень. Підтверджує FR-9, FR-17.
- **SM-4** Розбіжності між джерелами для Черкас видимі: щоразу, коли сайт і API розходяться, екран порівняння (FR-8) показує різницю. Підтверджує FR-8.
- **SM-C1** Не оптимізувати частоту сповіщень: більше не означає краще; не збільшувати частоту фонового оновлення за рахунок батареї.

## 8. Відкриті питання
1. Підтвердити початкові значення: мінімум 15 хв, застаріло після 1 год, історія 14 днів.
2. Як нормалізувати формати API (yes/no/first/second/mfirst/msecond) і що робити з областями зі застарілими файлами?
3. Мова застосунку: лише українська?

## 8.1 Ризики
- **Неофіційне джерело.** API OE_OUTAGE_DATA без ліцензії, на безкоштовному хостингу, частина областей застаріла (напр., Львів, Прикарпаття). Для Черкас 10 листопада API розійшовся з офіційним постом у 9 з 12 підчерг. Мітигація: FR-8, FR-9, мітка «неофіційне».
- **Скрейпінг сайту обленерго.** Структура сторінки може змінитися; умови використання не перевірені. Мітигація: стан «структура змінилася», кеш.
- **Обмеження iOS.** Ліміт 64 локальних сповіщень, непередбачуване фонове оновлення. Мітигація: FR-1, FR-14 (без сервера).
- **Публічний випуск.** Не розглядається; якщо рішення зміниться, потрібна перевірка ліцензії API, умов сайту і політики конфіденційності.
- **Приватність.** Місця зберігаються лише локально; облікові записи й аналітика відсутні у v1.

## 9. Індекс припущень
- FR-14/FR-18 — фонове оновлення iOS не гарантує інтервал.
- FR-1 — ліміт 64 сповіщень, планування лише найближчих.
- FR-9/FR-17/FR-4 — пороги: 1 год / 15 хв / 14 днів.
- Пресети кольорів — перелік уточнити при дизайні.
